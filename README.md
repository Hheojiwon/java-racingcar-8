# java-racingcar-precourse

## 기능 요구 사항

초간단 자동차 경주 게임을 구현한다.

* 주어진 횟수 동안 n대의 자동차는 전진 또는 멈출 수 있다.
* 각 자동차에 이름을 부여할 수 있다. 전진하는 자동차를 출력할 때 자동차 이름을 같이 출력한다.
자동차 이름은 쉼표(,)를 기준으로 구분하며 이름은 5자 이하만 가능하다.
* 사용자는 몇 번의 이동을 할 것인지를 입력할 수 있어야 한다.
전진하는 조건은 0에서 9 사이에서 무작위 값을 구한 후 무작위 값이 4 이상일 경우이다.
* 자동차 경주 게임을 완료한 후 누가 우승했는지를 알려준다. 우승자는 한 명 이상일 수 있다.
우승자가 여러 명일 경우 쉼표(,)를 이용하여 구분한다.
* 사용자가 잘못된 값을 입력할 경우 IllegalArgumentException을 발생시킨 후 애플리케이션은 종료되어야 한다.

##  고민한 점


### 1️⃣ 클래스 역할에 대한 고민
- 각 클래스가 **단일 책임 원칙** 을 지키도록 구조를 고민했다.
- 처음에는 `Car`와 `Cars` 두 클래스만으로 게임을 진행했지만,  
  게임의 흐름 제어가 컨트롤러에 노출되고, 로직을 재활용하기 어려운 문제가 있었다.
- 따라서 **게임의 핵심 흐름을 제어하는 `RacingGame` 클래스**를 추가로 도입했다.

####  Car
- 자동차 이름 저장
- 위치 초기화 및 이동 수행
- 이동 결과(위치) 저장

####  Cars
- `Car`들을 일급 컬렉션으로 관리
- 전체 자동차의 이동 제어 (`moveAllCars`)
- 우승자 판별

####  RacingGame
- 게임의 핵심 흐름 제어 (한 라운드씩 진행)
- 입력받은 시도 횟수만큼 레이스 반복 수행
- `Cars`와 `RandomNumberGenerator`를 이용해 실제 게임 로직 수행

---

### 2️⃣ 입력 처리 및 검증 클래스 설계 방식
- 문자열 파싱(`InputParser`)과 검증(`Validator`)의 책임을 분리하여 각 클래스가 하나의 역할만 가지도록 설계했다.
- 또한 처음에 컨트롤러에서 입력값 검증과 예외 처리를 모두 처리했으나, 코드가 복잡해지고 재사용성이 낮아지는 문제가 있었다. 따라서 `NameValidator`와 `AttemptValidator`로 예외 처리와 검증 로직을 분리하였다.
- **불필요한 객체 생성을 방지**하기 위해 이 두 클래스의 메서드를 `static`으로 선언했다.
- 현재 이름 길이 제한 규칙은 변경 가능성이 낮다고 판단했기 때문에 확장성보다 **간결함과 효율성**을 우선시하여 정적 메서드 방식을 선택했다.

---

### 3️⃣ 예외 처리 구조에 대한 고민
- 지난 문자열 계산기 미션에서 다른 분들의 코드를 보며 커스텀 예외(`CarException`)의 필요성을 배울 수 있었고, 이번 미션에 직접 적용해보았다.
- 예외 메시지를 한 곳에서 관리하기 위해 `ErrorMessage` 클래스를 별도로 두어  
  메시지 중복과 유지보수 문제를 해결했다.
- 이를 통해 예외 발생 시 명확한 의미를 전달할 수 있고, 코드의 일관성을 유지할 수 있었다.

---

### 4️⃣ 의존성 관리 (RandomNumberGenerator)
- `RandomNumberGenerator`의 의존 위치에 대해 고민이 있었다.
- `Cars`가 자동차들의 이동을 담당하지만,  
  게임의 흐름 제어와 랜덤 의존성은 `RacingGame`에서 관리하는 것이 적절하다고 판단했다.
- 이유는 `RacingGame`이 “게임의 한 턴”을 책임지고 있기 때문에 랜덤 값 생성도 해당 단계에서 주입받는 것이 책임 분리에 더 적합하다.

---

### 5️⃣ 테스트 코드 설계에 대한 고민
- 테스트 작성 시 `JUnit`의 `assertEquals`와 `AssertJ`의 `assertThat()` 중 어떤 것을 사용할지 고민했다.
- 학습 과정에서 `AssertJ`가 가독성과 표현력 면에서 더 뛰어나다고 느꼈고,  
  실제 예외 메시지나 흐름을 더 명확하게 검증할 수 있기 때문에 `assertThat()`을 선택했다.
